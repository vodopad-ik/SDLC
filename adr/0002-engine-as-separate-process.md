# ADR 0002 — Engine как отдельный процесс (локальный микросервис)

- **Статус**: принято (2026-10-18)

## Контекст
Elor сейчас — ассистент для звонков, в будущем — вычислительный движок образовательного приложения.

## Решение
Два исполняемых файла: `elor-engine.exe` (headless: аудио, VAD, STT, логика ходов, LLM, сессии) и
`elor-app.exe` (Qt Quick UI). Связь — WebSocket на `127.0.0.1` со случайным портом и токеном, JSON-протокол v1 (`docs/API.md`).

## Альтернативы
- Монолит (UI и ядро в одном процессе): проще старт, но ядро нельзя переиспользовать, падения общие.
- gRPC: строгие схемы, но тяжелее зависимость и сборка; WebSocket+JSON достаточно для v1, переход на gRPC — v2.

## Последствия
- UI управляет жизненным циклом engine (`QProcess` + Job Object), умеет переподключаться.
- Протокол версионируется; аудио по API не ходит — только текст/события.
- Накладные расходы < 1 мс на сообщение — несущественны.
